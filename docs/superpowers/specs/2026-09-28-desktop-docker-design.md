# Electron + Docker 桌面封装设计（2026-09-28）

用户已选择此前提出的 Electron＋Docker 本地方案，并授权封装。沿用 React 与 FastAPI/Neo4j；新增独立 desktop 目录，复用业务 API。目标产物为 Windows 安装程序、离线服务镜像包、安装使用说明；可将安装程序与镜像包放在同一交付目录。

桌面主进程：单实例，隔离渲染器，关闭 nodeIntegration、开启 contextIsolation/sandbox；仅暴露固定配置、启动、状态接口。运行本地 HTTP 服务，课程页面使用同源 /api 代理，禁止跨来源调用，静态路径限制资源根目录。生产课程 UI 编译为相对 API 地址，开发版不变。启动页与设置在 /desktop，课程页面在 /，桌面壳用 iframe 复用现有 UI；课程路由不会嵌套桌面壳。

服务管理器：先检查 Docker CLI/引擎，可启动已安装的 Docker Desktop，缺失时提供官方安装入口。检查本机已有受 Docker 管理的本项目 backend:8000，身份确认后复用，避免已有课程迁移和 Neo4j 数据目录并发访问。复用模式不停止已有容器、不更改其密钥。否则启动独立 Compose 项目 knowtrace-desktop，固定本地端口 18000，Neo4j仅容器内访问，使用独立命名卷。端口冲突明确报错。退出应用保持服务和数据；提供停止桌面自建服务按钮，绝不删除卷。

API 配置：密钥通过 Electron safeStorage 加密保存在 userData；不带入源码、镜像、安装包、日志。启动桌面自建服务时临时写受限 env 文件到用户目录并交给 Compose，运行完成删除；数据库口令随机生成并加密保存且复用。密钥更新在下一次自建服务启动生效；复用已有开发服务时明确提示其配置由原项目管理。重装/升级保留用户数据。

镜像分发：现有后端镜像较大，安装程序与离线服务镜像分开交付，避免安装包格式大小限制。安装程序包含 UI、Compose 与服务管理代码，镜像包可通过设置选取，也自动查找安装程序旁文件；找不到时显示具体缺失，不假装可启动。生成镜像必须从现有依赖环境复制干净应用代码，并清除 .env、用户上传/缓存/数据；采用容器根文件系统导出再导入，避免旧层残留凭据。压缩镜像包包含固定版本 backend 与 Neo4j，提供校验文件；用户课程数据库不包含其中。模型仍需联网访问 DeepSeek。

验收：真实镜像检查不含 .env/API密钥；安装包生成；独立 Compose 启动后 courses/graph 接口可用；新环境上传/抽取通过；复用模式读取现有课程且不写其数据；桌面 UI 真实启动或在不可访问原生窗时用同一 HTTP 页面验证并明确边界；启停/错误、配置加密、路径穿越与代理来源限制测试。说明 Docker 是安装前提，独立数据与现有开发数据区别、复用模式配置行为、离线镜像导入耗时和联网 API 要求。不加账号、云同步或自动更新。
