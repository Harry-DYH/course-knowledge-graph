# 比赛闭环补齐与功能增强设计

用户已授权按现有理解实现，并要求先跑通闭环，再补可直接落地的功能。本轮基于现有独立 React UI、FastAPI 和 Neo4j 继续集成。

## 验收链路

TXT 与 DOCX 上传抽取 → 课程独立图谱 → 教师修改并保存 → 刷新读取 → 学生掌握状态 → 基于先修边计算路径 → 当前课程问答、资料出处片段与教师修订优先。测试使用自编样例，不作为真实准确率认证。

## 功能与边界

补问答出处片段、真实错误处理、教师关系修订对回答的优先级、撤销重做与未保存提示、图谱 JSON 导出、学习目标已掌握提示。增加可持久化的处理任务记录和失败重试；上传状态呈现已发生的处理阶段，不伪造百分比。增加以当前课程图谱定义为依据的自测题与评分、课程统计、可导出的验收结果。

数据按课程、学习者标识隔离。当前学习者仍是本地演示身份，正式登录鉴权另列交付缺口。图谱保存验证版本、端点、重复边与先修环。资料原文与教师编辑分开记录，不把教师内容伪装成文档原文。API Key 不进入图谱、导出或文档。

## 验证

进行两种格式实际上传、教师修订持久化与版本冲突、循环关系拒绝、进度刷新读取与路径过滤、跨课程出处隔离、无资料依据问题拒答、自测评分一致性。保存实测时间与测试范围。真实课件、人工标注、教学关系审核、比赛团队信息与提交规格需要用户提供。

## 重试规则与补充验收

任务按课程和原文件名记录。失败任务只允许所属课程重试，处理中的任务拒绝重复重试；处理超时后标记失败。重试复用原上传文件及原始 Document，从上次处理位置继续；若原始抽取已完成，直接执行幂等课程导入。已关联文档再次导入不增建课程节点和边；新增资料导入保留已有节点字段及教师删除记录，不覆盖教师修订。原始资料的部分抽取结果保留为恢复依据，失败任务不会被当作已完成课程资料。

补验收：模拟抽取已完成、导入中断后的失败任务，重试前后课程节点/边数量和教师修订不变；重复重试返回冲突。同课程两个学习者的掌握状态、路径和自测历史不串用；教师保存的先修关系与原文冲突时，路径使用课程边，问答优先采用课程关系并单列教师修订来源，原资料片段仍清楚标为原资料。
