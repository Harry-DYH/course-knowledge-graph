## 本机启动

课程界面使用 http://127.0.0.1:3015/ ，后端文档使用 http://127.0.0.1:18000/docs 。本机已有其他项目使用 8000 端口，因此本项目改用 18000。

从仓库根目录运行：

```sh
bash start-testing.sh
```

保持终端运行。按 Ctrl+C 会停止该脚本启动的后端和界面，数据库和数据会保留。若提示端口占用，先关闭之前启动的本项目服务；脚本不会终止占用端口的其他程序。

数据库使用 Docker Compose 项目 `ckg-accuracy`，容器 `ckg-accuracy-database-1`，数据卷 `ckg-accuracy_neo4j_data`。Neo4j 为 5.26.0，APOC 为 5.26.0，连接配置已写入本机 `backend/.env`。这一数据卷与其他项目分开，但同一数据卷内的多次测试仍可能相互影响。

后端使用 `backend/.venv` 中的 Python 3.12；课程界面使用 `ui-reference/`。`frontend/` 是原项目调试界面，本次没有启动它。

## 配置 DeepSeek

本机 Key 已于 2026 年 10 月 9 日配置，官方模型列表接口鉴权通过。当前配置使用 `deepseek-flash`；下面仅展示脱敏格式，更换 Key 时编辑 `backend/.env` 中对应项：

```dotenv
LLM_MODEL_CONFIG_DEEPSEEK_DEMO="deepseek-flash,https://api.deepseek.com,REPLACE_WITH_YOUR_DEEPSEEK_API_KEY"
```

保存后重启后端，使配置生效。密钥只保存在被 Git 忽略的本机文件里，不写进报告或提交到仓库。课程入口使用 `deepseek_demo`，但上游 `example.env` 未包含对应配置项，本机已补齐该项。当前账号模型列表返回 `deepseek-flash` 和 `deepseek-v4-pro`，因此将先前准备的 `deepseek-chat` 改为 `deepseek-flash`；这与[官方当前接入文档](https://api-docs.deepseek.com/zh-cn/)一致。要复现队友的旧结果，还需确认其实际模型版本及参数，不能仅凭同为 DeepSeek 判为相同实验条件。

课程界面地址配置在 `ui-reference/.env.local`：

```dotenv
VITE_BACKEND_API_URL=http://127.0.0.1:18000
```

本地向量模型 `all-MiniLM-L6-v2` 已下载到 `backend/local_model`，输出为 384 维，不需要额外的向量服务 API Key。

## 开始实际测试

当前 Key 已生效，已通过两点 TXT 冒烟；随后真实章节的 TXT、DOCX 测试均在内容补全阶段失败，尚未通过完整章闭环。可在课程页面的教师端创建测试课程，再上传 `demo/软件架构基础_闭环样例.txt` 或自己的测试资料。上传会真实调用 DeepSeek，包含知识抽取及后续属性补全。

完整功能冒烟命令如下，从仓库根目录运行：

```sh
TEST_BASE_URL=http://127.0.0.1:18000/course_workspace \
  backend/.venv/bin/python -m pytest backend/tests/test_smoke.py -v
```

这套测试需要真实模型调用，有些用例会因数据不足而跳过，另有一个删除课程用例只是占位。它验证功能流程，不计算抽取准确率。不要把 pytest 通过率当作抽取准确率。

抽取与结果接口可在后端文档中操作：

1. `POST /course_workspace/courses` 创建课程。
2. `POST /course_workspace/courses/{course_id}/upload` 上传资料并完成处理。
3. `GET /course_workspace/courses/{course_id}/graph` 保存最终 `points` 和 `edges`；教师编辑页也支持 JSON 导出。

评测前保存原始输出，避免将教师人工修订后的图谱混入模型准确率。

## 正式准确率测评的基准

上层 `doc/` 中的赛题要求人工抽样验证的知识抽取准确率不低于 70%，但没有定义计算公式；《项目详细方案》第 9.2 节提出计算 F1，目标不低于 70%。两者口径需要在正式报告里说明，不能直接等同。赛题还要求以课程一章为基准，实体不少于 20 个、关系至少 3 类，至少支持 2 种文档格式，解析与抽取合计不超过 60 秒，问答不超过 15 秒。

原《知识抽取准确率测试报告》明确未提供人工真值统计的精确率、召回率或 F1。自编软件架构样例的 20 个知识点、27 条关系和约 10 秒耗时是历史流程结果，不能证明 70% 达标。本轮已新增可离线复算的评分器与 70 个知识点、101 条关系的冻结 AI 辅助参考集，仍没有人工确认的完整真值集；证据保存在 `evaluation/2026-10-09-hello-tree/`。

本轮已选用《Hello 算法》第 7 章完成初测。下一步先处理分块截断与补全失败，再由课程熟悉者复核参考知识点、关系三元组、方向、别名及粒度，并补查遗漏。正式指标分别计算节点与关系的精确率（正确数／预测数）、召回率（正确数／人工真值数）和 F1；仅抽样检查输出不能衡量遗漏情况。本轮严格参考匹配分数和 AI 抽样结果均不能替代人工验收。

当前课程抽取固定使用 `deepseek_demo`、1500 token 分块、100 token 重叠、每次合并 1 块，关系为 `PREREQUISITE_OF`、`CONTAINS`、`RELATED_TO`。上传后还会进行属性补全。因此应明确测评最终课程图谱还是原始抽取图谱，并记录提交号、模型名、原始材料、配置、时间、原始响应和逐条判定。

本轮发现默认 `MAX_TOKEN_CHUNK_SIZE=10000` 导致整章的 13 块只保留前 6 块，约覆盖 47% 的正文 token。当前评分对象为失败后保留、未经教师编辑的课程图谱，不能称为完整章节的成功输出。

正式运行应使用全新的独立数据库或数据卷。同名资料可能复用旧抽取结果，删除课程也不会清除所有原始实体和关系；仅改文件名或删课程不足以保证重复实验独立。当前数据卷已用于环境验证，应与正式测评数据分开管理，不要清理其他项目的数据。

本次 TXT、DOCX 教材实测已各使用独立空数据库，测试容器已停止、数据卷保留。后续修复复测应另建批次，不覆盖本轮输入、参考、日志或评分。
