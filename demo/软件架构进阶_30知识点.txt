# 软件架构进阶：30 个知识点展示样例
人工编写的演示数据，用于观察布局和学习路径。非教材抽取结果。

## 基础准备 / 编程基础（概念）
程序通过变量、控制流程与表达式描述计算过程。
例子：用条件判断验证输入是否为空。

## 基础准备 / 需求分析（方法）
识别用户目标、使用场景及系统约束，形成可验证的需求。
例子：明确课程系统需要支持知识图谱查询和学习进度保存。

## 基础准备 / 数据库基础（概念）
数据库以结构化方式持久化数据，并支持查询与更新。
例子：将课程、知识点和学习记录保存到数据库。

## 基础准备 / 网络基础（概念）
理解客户端与服务端通过网络地址、端口和协议交换数据。
例子：浏览器通过本机端口访问后台服务。

## 需求与程序结构 / 函数（概念）
函数将一段可复用的操作封装为具有输入和输出的单元。
例子：将先修条件检查封装成独立函数。

## 需求与程序结构 / 数据结构（概念）
数据结构规定数据的组织方式及访问操作。
例子：使用邻接表存储知识点之间的先修关系。

## 需求与程序结构 / 功能需求（概念）
功能需求描述系统必须提供的具体行为和服务。
例子：教师可以创建、修改和删除知识点。

## 需求与程序结构 / 非功能需求（概念）
非功能需求描述性能、可靠性、安全性等质量要求。
例子：学习路径查询在规定规模下及时返回。

## 需求与程序结构 / SQL（工具）
SQL 是用于关系数据库查询和数据操作的语言。
例子：通过 SELECT 查询某个学生的学习记录。

## 需求与程序结构 / HTTP（协议）
HTTP 规定客户端与服务端请求、响应及状态码的语义。
例子：POST 提交新的课程，GET 获取课程信息。

## 系统设计 / 模块化（方法）
模块化按职责划分程序，并通过明确接口协作。
例子：将图谱、问答和学习路径拆为独立模块。

## 系统设计 / 用例建模（方法）
用例以参与者与系统交互描述完成目标的过程。
例子：学生选择课程、计算路线并标记掌握。

## 系统设计 / 性能指标（指标）
性能指标以响应时间、吞吐量和资源使用等量化系统表现。
例子：记录路径接口的耗时和处理知识点数量。

## 系统设计 / 接口设计（方法）
接口设计明确调用者和被调用者之间的数据、行为及错误约定。
例子：路径接口返回有序步骤、缺少先修和当前可学状态。

## 系统设计 / 数据建模（方法）
数据建模定义实体、属性、关系及一致性约束。
例子：定义课程与知识点的一对多关系及先修边。

## 架构与数据优化 / 高内聚（原则）
高内聚要求模块内部职责紧密相关，围绕明确目标组织。
例子：学习路径模块只负责依赖计算与推荐。

## 架构与数据优化 / 低耦合（原则）
低耦合通过稳定接口减少模块对彼此内部实现的依赖。
例子：前端通过公开 API 获取路线，而不直接读取数据库。

## 架构与数据优化 / 分层架构（架构）
分层架构将系统职责划分为表现、业务和数据访问等层。
例子：页面展示、推荐算法和数据库查询分别放在对应层。

## 架构与数据优化 / REST接口（方法）
REST 接口以资源和统一操作语义组织服务访问。
例子：用 GET /courses 获取课程资源集合。

## 架构与数据优化 / 索引优化（方法）
索引优化根据查询条件建立合适的索引以减少扫描成本。
例子：为经常查询的课程标识建立索引。

## 工程实现 / 依赖注入（方法）
依赖注入由外部提供组件所需依赖，减少内部固定绑定。
例子：为推荐服务注入可替换的知识图谱仓库。

## 工程实现 / 组件设计（方法）
组件设计把职责明确、接口稳定的模块组合成可协作单元。
例子：图谱组件接收节点与关系，并输出知识点选择事件。

## 工程实现 / 缓存设计（方法）
缓存保存可复用结果，并规定失效策略以平衡速度和一致性。
例子：按课程修订号缓存图谱，修改后使旧缓存失效。

## 工程实现 / 事务管理（机制）
事务管理保证关联的数据操作满足一致性要求。
例子：修改节点与关系在同一事务中提交，失败时回滚。

## 工程实现 / 身份认证（机制）
身份认证验证访问者身份，并为后续访问控制提供依据。
例子：教师登录后才可进入教师编辑入口。

## 测试与交付 / 单元测试（方法）
单元测试独立验证函数或模块的行为与边界情况。
例子：验证存在多个先修时必须全部掌握才能推荐目标。

## 测试与交付 / 集成测试（方法）
集成测试验证多个组件协作时的数据传递和行为。
例子：保存掌握状态后检查推荐接口与页面同步更新。

## 测试与交付 / 日志监控（方法）
日志监控收集运行事件和指标，用于发现故障与定位原因。
例子：记录课程解析失败的任务标识和错误信息。

## 测试与交付 / 容器部署（工具）
容器部署将运行环境及应用打包，并通过配置启动服务。
例子：分别启动前端、后端与数据库容器并配置健康检查。

## 测试与交付 / 系统可维护性（质量属性）
可维护性衡量系统理解、修改、验证和持续演进的便利程度。
例子：通过职责分离、自动测试和运行日志降低修改成本。
